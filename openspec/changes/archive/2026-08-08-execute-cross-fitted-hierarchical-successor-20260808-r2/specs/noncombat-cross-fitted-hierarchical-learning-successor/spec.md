## ADDED Requirements

### Requirement: The 20260808-r2 authorization is consumed by one bounded terminal execution
The system SHALL invoke at most one logical execution identity from the exact
pushed 20260808-r2 registration, request, delegated approval, and authorization.
It SHALL preserve the registered source, native/runtime/isolation identity,
output root, complete 8x64 primary schedule, 576-access reserve, eight-update
ceiling, 14,400 charged-second ceiling, estimator/objective, saturation gate,
and retry/resume contract. While the true execution process is alive, external
monitoring SHALL observe process liveness only and SHALL NOT inspect or mutate
the active output root. After exit, an independent verifier SHALL classify and
preserve the closed terminal bundle. The change SHALL make no policy-quality,
formal-RL, evaluation, gameplay, qualification, or promotion claim.

#### Scenario: Exact preflight passes and execution starts
- **WHEN** all pushed control blobs and source/readiness/native/runtime/isolation
  identities revalidate, no conflicting process exists, and the registered
  output root is absent
- **THEN** the real isolated `execute` entry point may create the output root,
  load only the registered dependencies, and access only the registered
  schedule within every resource ceiling

#### Scenario: Preflight fails before first-seed marker
- **WHEN** any exact source, path, identity, approval, authorization, output,
  lease, isolation, or dependency check fails before empirical seed access
- **THEN** the system stops without substituting a term or seed and permits only
  the identical manual pre-start reopening explicitly allowed by the registered
  lifecycle

#### Scenario: Execution is alive
- **WHEN** the true Python execution process or its registered child remains
  alive and holds the logical identity
- **THEN** external monitoring reads process liveness only and does not list,
  hash, open, copy, verify, or mutate any active-output artifact

#### Scenario: One infrastructure interruption qualifies
- **WHEN** durable evidence after first-seed access uniquely proves the exact
  registered same-identity infrastructure interruption and unused resume
  allowance
- **THEN** at most one manual resume restores the exact checkpoint and incomplete
  chunk without changing a source, seed, term, threshold, or output identity

#### Scenario: Execution closes normally or negatively
- **WHEN** the run completes eight chunks, triggers the exact four-chunk family-
  saturation gate, or publishes another structurally valid registered terminal
- **THEN** the independent verifier preserves that terminal result without
  evaluation, tuning, retry, or policy-quality reinterpretation

#### Scenario: Execution fails without resume eligibility
- **WHEN** integrity, algorithm, resource, ordinary terminal, ambiguous-output,
  or exhausted-resume evidence prevents valid completion
- **THEN** the system preserves the failure under the consumed identity and
  does not rerun, replace a seed, raise a bound, or create a successor proposal
  inside this change
