## Why

The LightSTS guard-transfer POC and a separately collected fresh real replay both support a latent-gated legal action correction recipe, but the fitted heads currently exist only inside exploratory reports. A source-bound development fit is needed now to turn that repeated offline evidence into one reproducible, serializable candidate artifact before considering any gameplay evaluation.

## What Changes

- Add a deterministic CPU runner that fits the frozen-parent latent gate from fixed LightSTS guard labels plus a bound development replay, then fits the legal correction head only from changed development rows.
- Calibrate the gate threshold only on the development replay under a fixed direct-open cap; evaluate without fitting on separately bound replay checkpoints.
- Emit one atomic, non-production adapter artifact and a machine-readable report containing exact input/source identities, objective telemetry, round-trip evidence, and fixed eligibility checks.
- Keep the execution interface lightweight: ordinary repository authorization is sufficient, while immutable inputs, fixed seeds, no in-place overwrite, and no in-place tuning after a scientific failure provide the reproducibility boundary.
- Treat the existing POC r3 and fresh confirmation as evidence for preregistering metrics, not as production qualification.

## Capabilities

### New Capabilities
- `combat-rl-latent-gated-candidate-fit`: Defines source-bound fitting, independent replay evaluation, serialization, reporting, and authority boundaries for a development latent-gated combat correction candidate.

### Modified Capabilities

None.

## Impact

- Adds a focused analysis runner and regression tests around the existing `spirecomm.ai.rl.v2.latent_gated_adapter` API.
- Reads fixed LightSTS inputs, the production-r16 parent identity, one development replay, and separately bound evaluation replay checkpoints; it does not modify those inputs.
- Success requires exact parent immutability and artifact round trip plus the preregistered direct-open, changed-open, direct-agreement, changed-correction, overall-uplift, and positive-energy EndTurn checks on every bound evaluation replay.
- Non-goals are CommunicationMod integration, online learning, game launch, production checkpoint replacement, policy promotion, and claims based on the fitting corpus alone.
- Rollback is deletion or non-use of the development artifact; production r16 and agent routing remain unchanged.
