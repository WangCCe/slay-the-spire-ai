## Why

Formal non-combat RL remains blocked because Current has four frozen bridge
rows but no completed own-trajectory row under the repaired API v3 adapter.
Two fresh cohorts already failed before one row, so the least risky next step is
a structural diagnostic on fixed, already consumed development seeds rather
than another fresh cohort or training run.

## What Changes

- Add a separately registered Current bridge diagnostic smoke over exactly
  seeds `7000`, `7100`, `2000`, and `10`, selected from existing evidence for
  the repaired Scrap Ooze, shop-remove sentinel, The Cleric, and Courier support
  boundaries. Run two deterministic replays per seed with no runtime override.
- Bind the existing shop-support successor module, adapter and simulator
  provenance, Current bridge and policy sources, event and shop contracts,
  metadata, runtime, predecessor failures, fixed limits, and all-false
  downstream authority before any environment is constructed.
- Preserve a terminal row or exact declared support-blocker row for every fixed
  seed. Continue past deterministic Courier support blockers, but stop on the
  first unknown structural, identity, legality, replay, timeout, or mutation
  failure without replacement or retry.
- Publish canonical machine-readable artifacts and a no-native verifier. A
  structural pass requires at least one complete terminal Current row,
  deterministic accepted rows for the full fixed seed set, and nonzero route,
  shop, event, and card-reward coverage across retained prefixes.
- Keep fresh evidence, baseline-floor, policy-quality, reward, OPE, formal-RL,
  training, gameplay, qualification, policy/model loading, and promotion
  authority false.

No live gameplay evidence is created. Success only removes the missing Current
own-trajectory structural blocker and permits a later read-only readiness
refresh; it does not define or pass a baseline floor.

## Capabilities

### New Capabilities

- `noncombat-current-bridge-diagnostic-smoke`: Defines the frozen reused-seed
  diagnostic registration, deterministic terminal/support-blocker row contract,
  fail-closed verdicts, canonical verification, and no-authority boundary.

### Modified Capabilities

None.

## Impact

The change is limited to one compact offline evaluator and verifier, focused
tests, a fixed registration, canonical reports, OpenSpec artifacts, and the
project-direction handoff. It may import the exact registered native module and
construct only the four registered development-seed environments after a
pushed preregistration gate. It does not modify Current policy, the adapter,
simulator, bridge semantics, reward, models, Communication Mod, or gameplay.

Before the execution journal starts, rollback may remove the new evaluator and
unexecuted registration. After execution starts, rollback must preserve the
registration, journal, and pass, support-limited, failure, timeout, or partial
result; the fixed diagnostic may not be repaired and rerun under the same
identity.
