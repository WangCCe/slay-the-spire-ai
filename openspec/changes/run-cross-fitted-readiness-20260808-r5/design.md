## Decisions

### Use one immutable final planning commit

The r5 delta SHALL be synced to the canonical readiness spec, strictly
validated, committed, and pushed before a final source exists. That final
source must descend from
`c977a877fd319ff8bdfe6cb2145c1f9d8cdd3f3d` and differ from it by exactly the
five r5 change files plus the modified canonical readiness spec. The exact
40-character `HEAD == origin/master` value after push is the only eligible
source. No tracked file self-references that future hash.

Alternative: run directly from `c977a877f`. Rejected because that source does
not preregister r5 and its canonical readiness contract names only earlier
attempts.

### Bind r4 as immutable historical evidence

Preflight checks the exact six tracked r4 files and their registered sizes and
SHA-256 digests: started and verified receipts, candidate inventory, JSON and
Markdown reports, and closeout. It also reuses the auditor's complete historical
source/consumed-evidence bindings. r4 output is never parsed as empirical
outcome access or retried.

Alternative: depend only on r4's reported identity. Rejected because exact
tracked bytes are cheap to bind and prevent silent historical substitution.

### Resolve authorization through the standing delegation at orchestration

The external human grant is the maintainer's 2026-08-08 message in the current
Codex task asking not to require such precise authorization because this is a
solo repository and stating that Codex may fully represent the maintainer. The
authoritative revocation source is the same current Codex task. User messages
are ordered by the host-provided task sequence, and the latest explicit user

all-false source-only audit. Codex must recheck that no later explicit human
revocation exists immediately before committing/pushing the plan and again

This is intentionally separate from delegated-approval v2, whose request class
is the empirical successor execution request. r5 grants no successor execution

Alternative: broaden delegated-approval v2 to readiness. Rejected because it

credential approvals remain external mandatory controls.

### Treat the source-keyed claim as irreversible

Once `attempt_started.json` exists, every exit, exception, timeout, no-go,
verifier failure, cleanup failure, or publication failure consumes the source.
There is no retry, resume, alternate audit id, changed path, or wider limit.

### Verify only durable outcomes after process exit

An installed output is checked by the standalone standard-library verifier
against the exact source. With no output, an independent Python `-I` receipt
review checks canonical schemas, digests, all-false maps, limits, and path
absence without importing project, auditor, verifier, Torch, native, runtime,
or model modules. Neither outcome authorizes retry.

## Risks / Trade-offs

- **A remaining source-only defect consumes r5** -> Preserve the one-shot rule;
  any correction requires a new source proposal.
- **Standing delegation is overread as empirical authority** -> Limit it in the
  pushed plan to this exact all-false readiness command; successor registration
  and execution remain separate future stages.
- **An unrecorded revocation is missed by code** -> Codex orchestration checks
  the latest task state before publication and invocation; the renderer or
  auditor does not claim conversation discovery.
- **r4 evidence is accidentally treated as input data** -> Bind it for
  preservation while the repaired namespace exclusion runs before seed loading.
- **The audit is long** -> Permit one 7,200-second outer wait while retaining
  every existing internal time and byte ceiling.
- **A `go` is overinterpreted** -> Keep all empirical, training, policy, and
  promotion authority false in report, receipt, closeout, and project direction.
