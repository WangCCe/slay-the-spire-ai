## Goals / Non-Goals

**Goals:**

- Preserve the exact human grant and real task/message provenance in one
  canonical reusable standing-delegation manifest.
- Resolve the delegation to exactly the pushed r2 request and independently
  review the complete transitive binding.
- Publish approval before deriving and publishing authorization.
- Stop with an authorized but unstarted execution and an absent registered
  output root.

**Non-Goals:**

- Changing registration, request, source, native/runtime identity, cohort,
  resources, retry/resume terms, authority shape, model, or algorithm.
- Bypassing Codex host or operating-system approvals.
- Loading native, Torch, model, or checkpoint code; constructing an
  environment; accessing a seed; fitting; training; evaluation; gameplay;
  CommunicationMod; qualification; promotion; or policy claims.
- Executing or resuming the registered experiment in this change.

## Decisions

### Use the exact human message provenance

Build the standing delegation with the exact grant sentence, UTC message time,
message ID, task ID, and `external-human-message` source. Its scope and
exclusions are generated by the tracked producer, including the ban on changing
request-bound terms and bypassing host approval.

Alternative: invent a repository-local maintainer ID or use the current `好
继续` message as the grant. Rejected because either would weaken provenance or
misrepresent the human text.

### Check revocation immediately before approval rendering

Re-read the current task's user-message metadata immediately before approval
publication. Any explicit revocation after `item-22027` stops the stage. Record
the latest checked user message and check time in the review; the canonical
delegation retains the contract's future-revocation rule.

Alternative: treat the historical grant as irrevocable. Rejected because the
standing-delegation schema explicitly reserves future human revocation before
approval publication.

### Render through isolated source-only entry points

Use Windows Python `-I -c` with only the exact repo root inserted into
`sys.path`. Build the delegation through the tracked pure helper, then invoke
`inspect-delegation`, `render-delegated-approval`, and
`render-authorization`. Capture stdout to additive staging files and publish
only after canonical byte round-trip equality and independent validation.

Alternative: hand-author JSON or call the experiment file directly under
`-I`. Rejected because hand-authored digests are error-prone and direct file
execution cannot import the repo package in isolated mode.

### Separate approval and authorization commits

The approval publication commit contains only the standing delegation,
delegated approval, review, and task evidence. It is pushed and re-read from
`origin/master` before authorization is derived. Authorization and its review
are then published in a second commit. Neither commit creates the registered
output root.

Alternative: publish both in one commit. Rejected because the canonical
lifecycle requires independently reviewable irreversible stages.

### Use evidence-only verification

Run focused control/verifier tests, source-only CLI validation, canonical
digest probes, import isolation, strict OpenSpec, and bounded independent
review. The long commit gate and gameplay validation are not applicable unless
implementation or test source unexpectedly changes.

## Risks / Trade-offs

- **Grant or task metadata is recorded incorrectly** -> Compare the manifest
  fields to the thread metadata before publication and fail closed on any
  mismatch.
- **A revocation appears during the approval stage** -> Repeat the metadata
  check immediately before rendering and stop without publishing approval.
- **Approval or request bytes drift before authorization** -> Re-read exact
  pushed blobs and require producer plus independent validation; never
  substitute a nearby path or digest.
- **Requested authority is mistaken for execution** -> Review and closeout
  assert output-root absence and all empirical operations false; execution is
  a later OpenSpec change.
