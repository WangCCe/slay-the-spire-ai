  delta requirement, exact control identities, execution command, monitoring
  boundary, recovery rule, success metric, and rollback boundary.

## 2. Revalidate The Irreversible Boundary

- [ ] 2.1 Confirm local `HEAD` equals `origin/master`, contains exact pushed

- [ ] 2.2 Revalidate the complete control chain through isolated producer and
  independent standard-library paths, including source/readiness, native file

  blocked-dependency import delta.
- [ ] 2.3 Confirm no same-identity execution process exists and freeze the exact
  real-argv `execute` command plus an outer wait longer than the registered

## 3. Execute And Monitor One Identity

- [ ] 3.1 Invoke the exact tracked execution command once, without changing a
  source, path, registration, request, approval, authorization, output, seed,
  resource, threshold, or retry term.
- [ ] 3.2 While the true execution process is alive, monitor liveness only; do
  not inspect or mutate the active output root and do not launch Slay the Spire
  or CommunicationMod.
- [ ] 3.3 If the invocation is interrupted, apply only an explicitly eligible
  identical manual pre-start reopening or the one registered same-identity
  post-start infrastructure resume; otherwise preserve failure without retry.

- [ ] 4.1 After the true Python process exits, acquire the lease through the

  control identities, process outcome, access/update/resource counts,

- [ ] 4.4 Record the long commit gate and fresh gameplay validation as not

- [ ] 4.5 Sync the delta requirement, update project direction, archive the

- [ ] 4.6 Stop without canary/holdout evaluation, OPE, production model loading,
