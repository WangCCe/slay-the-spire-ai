# Current Bridge Diagnostic Successor Eligibility Review

Date: 2026-08-03

## Decision

One separately preregistered successor diagnostic is eligible for proposal.
This is not permission to rerun, repair, resume, or replace the consumed
`noncombat_current_bridge_diagnostic_smoke_20260803` identity. It is permission
only to plan a new identity that preserves the old failure and tests the same
structural question after the independently completed candidate-schema fix.

Native loading, environment construction, seed access, execution, gameplay,
fresh evidence, readiness refresh, baseline-floor claims, OPE, model fitting,
reward changes, formal RL, training, qualification, and promotion remain
unauthorized by this review. Any execution authority must be explicit in the
successor OpenSpec and must follow a clean, pushed preregistration gate.

## Why A Successor Is Eligible

The consumed attempt finalized immutably and its no-native verifier still
recomputes the canonical failure. It reached one native snapshot, candidate
set, and Current evaluation, but failed on the runner's lookup of
`candidate["action_type"]` before `environment.step()`. It retained zero
decisions, rows, terminal outcomes, support blockers, or category counts. The
failure therefore supplied no transition or policy-quality result that a
successor could tune against.

The defect is deterministic and runner-only. The production candidate contract
contains exactly `action_id`, `available`, `category`, `kind`, `label`, and
`raw`; `action_type` belongs to the Current evaluation contract. Commit
`b0c7ccc0b` removed the invalid candidate dependency after a red regression,
kept evaluation metadata fail-closed, passed the adjacent focused suite and
registered commit gate, and preserved every consumed evidence byte.

The proposed cohort cannot create selection leakage. It must use only the same
four already consumed development seeds `[7000, 7100, 2000, 10]`, in the same
order, with two deterministic replays, the same 500-decision limit, the same
600-second wall limit, and the same declared Courier support boundary. No
outcome, prefix, seed, threshold, or support result from the failed attempt may
change those controls.

This matches the repository's accepted recovery rule: preserve the consumed
identity, diagnose and fix the source defect separately, then require a new
reviewed identity with one-shot authority. The teacher-sufficiency v1-to-r2
runtime recovery and qualification r7-to-r8 progression are precedents for the
identity boundary, not authority to reuse either old attempt. Both retained
their failed lineage and prohibited same-identity retries.

## Why This Is Only A Conditional Go

The current runner is 1,824 lines and its focused test module is 789 lines. Its
schema versions, seeds, registration path, output directory, evidence sources,
and publication logic are module globals. Copying the runner would create a
second large implementation; blindly changing those globals would break
historical artifact recomputation. Either approach would make infrastructure
risk larger than the structural question.

The successor proposal must therefore pass these offline gates before it may
request execution:

1. Preserve the consumed registration, closeout, journal, manifest, and all
   canonical artifacts byte-for-byte and keep their verdict failed.
2. Bind the consumed identity, exact failure boundary, candidate-schema fix
   commit, current runner/test bytes, native module, adapter/simulator source,
   metadata, contracts, runtime, and all-false authority.
3. Introduce one explicit profile boundary for versioned registration and
   publication identity. Do not copy the full runner or generalize unrelated
   experiment infrastructure.
4. Prove both profiles offline: the historical profile must still recompute
   the consumed artifact directory without native loading, while the successor
   profile must reject path, schema, lineage, source, cohort, limit, authority,
   and output drift before environment construction.
5. Exercise production-shaped candidates through the complete pre-step path
   and prove invalid evaluator `action_type` values fail before `step()`.
6. Run focused regressions, the partitioned commit gate, strict OpenSpec
   validation, and byte-identity checks before preregistration.
7. Publish and push a new registration and an absent new output root before any
   one-shot execution. A partial or failed successor is terminal and cannot
   prepare another identity inside the same change.

If the profile boundary cannot remain narrow or historical recomputation stops
being exact, the successor is `no-go` and the baseline lane pauses. A copied
runner, a changed cohort, a new seed, a relaxed stop rule, or an authority
increase is also an immediate `no-go`.

## Expected Value And Limits

A successful successor can establish only that Current completes at least one
own trajectory through the repaired supported boundary and that the fixed
reused-seed rows are deterministic. That removes the immediate structural
blocker and permits a separate read-only baseline-floor readiness refresh.

It cannot establish a credible baseline floor. All eight floor-study contract
checks remain false and must be fixed in a later proposal. It also cannot solve
the independent outcome-evidence blocker: current frozen evidence still has
zero deterministic-Current-supported victories. Formal non-combat RL therefore
remains `no-go` even if the successor passes.

## Next Step

Create a separate OpenSpec proposal for exactly one versioned successor
diagnostic. The proposal may authorize offline implementation and verification
first. It must keep native execution as a later, explicit, one-shot task after
the implementation and preregistration commits are clean, reviewed, pushed,
and independently reproducible.
